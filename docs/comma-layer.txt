================================================================
COMMA LAYER — a step towards Emacs "devil mode"
================================================================

This document describes the comma-leader feature that lives in index.ts
(sections "Comma layer (devil-mode leader)" and "Comma modifier layer
(collecting sticky modifiers)"), why it works the way it does, and the
reasoning behind the design. I keep it here so I can pick the feature up
again later / on another machine without re-deriving everything.


----------------------------------------------------------------
1. WHAT IT DOES (user-facing behavior)
----------------------------------------------------------------

On the BASE layer, comma (,) stops being a plain comma and becomes a
"leader" key, inspired by Emacs' devil-mode.

After tapping comma you are in the LEADER state:

  , + space/tab/enter/backspace/esc -> comma, then that key (i.e. ", ")
  , + a / s / d / f                 -> arm a sticky modifier and switch to the collecting state (see below)
  , + q/w/z/x/c/v                   -> the matching ⌘ shortcut (⌘+Q / ⌘+W / ⌘+Z / ⌘+X / ⌘+C / ⌘+V)
  , + g                             -> caps lock
  , + any other supported key       -> ignored, with a beep
  , alone (timeout) or  , ,         -> a single literal comma

Enter and backspace each have TWO physical positions in this 40%-ish layout, and both are accepted:
  - enter:     semicolon    AND return_or_enter
  - backspace: open_bracket AND delete_or_backspace

Once at least one modifier is armed you are in the COLLECTING state:

  a / s / d / f  -> keep toggling ⇧ / ^ / ⌥ / ⌘ (stay in the state so modifiers can be chorded)
  ,              -> escape back to the base layer, keeping any armed sticky modifiers (e.g. ", f , a" -> ⌘+A)
  any other key  -> leave the state and behave EXACTLY like the base layer, with the accumulated sticky modifiers applied

Examples:
  , q                -> ⌘+Q
  , f d q            -> ⌘+⌥+Q
  , f , a            -> ⌘+A   (comma escapes the collecting state without consuming ⌘)
  , f <hold>[ q      -> ⌘+'   (holding [ enters the symbol layer, where q produces a single quote)

ASCII map of the comma layer (mirrors the base-layer diagrams):

  // TAB ⌘+Q ⌘+W ___ ___ ___ ___ ___ ___ ___ ___ BSP
  // ESC  ⇧   ^   ⌥   ⌘   ⇪  ___ ___ ___ ___ RET
  // ___ ⌘+Z ⌘+X ⌘+C ⌘+V ___ ___ ___  ,  ___ ___
  //                       SPC


----------------------------------------------------------------
2. HOW IT IS IMPLEMENTED
----------------------------------------------------------------

Two Karabiner variables (layers) drive it:

  comma-layer       the LEADER state (just tapped comma, no modifier yet)
  comma-mod-layer   the COLLECTING state (>= 1 sticky modifier armed)

Base comma mapping (baseLayerComma):
  - on key-down: set comma-layer = 1
  - to_delayed_action.to_if_invoked (fires after COMMA_LAYER_TIMEOUT_MS,
    currently 2000ms, if no other key is pressed): output a single comma
    and set comma-layer = 0
  - The delayed action is CANCELED by the next key press, which is what
    lets ", <key>" behave as a chord instead of emitting a comma first.
    Note: because the timeout ends the leader by emitting a comma, keys
    pressed after the timeout are normal keys again (this is the usual
    leader/timeout trade-off).

Leader mappings (commaLayer, gated by ifLayer("comma-layer")):
  - commaThen(from, to): layerOff comma-layer + output comma + `to`
    (used by space, tab, esc, both enters, both backspaces)
  - commaTo(from, to, [modifiers]): layerOff comma-layer + output `to`
    (no comma), e.g. , z -> ⌘Z, , g -> caps lock (q/w/z/x/c/v and g)
  - commaStartModifier(from, modifier): comma-layer=0, comma-mod-layer=1,
    sticky_modifier(modifier, "toggle")  (used by a/s/d/f)
  - commaIgnore(from): layerOff comma-layer + beep (afplay Basso.aiff)
  - the comma key itself: layerOff comma-layer + output one comma
    (this is the ", ," -> "," case)

Collecting mappings (commaModifierLayer, gated by ifLayer("comma-mod-layer")):
  - collectStickyModifier(from, modifier): comma-mod-layer=1 (stay) +
    sticky_modifier(modifier, "toggle")  (a/s/d/f)
  - comma: escape back to base — sets comma-mod-layer=0 only (no comma
    output, does not re-enter the leader), so armed sticky modifiers stay
    and apply to the next key
  - spacebar: explicit, because spacebar is not part of baseLayer
  - EVERY OTHER KEY: generated by taking baseLayer and wrapping each
    mapping with exitCommaModifierLayer(), which prepends
    set comma-mod-layer = 0 to that mapping's `to`. So the key clears the
    collecting state and then does its normal base-layer thing (including
    duos), while Karabiner applies the still-armed sticky modifiers.

Manipulator order (first match wins in Karabiner) is:
  ... symbol/nav/visual/modifier/number/function/upper ...,
  commaLayer, commaModifierLayer, baseLayer
so the two comma states take priority over the base layer but sit below
the other feature layers.


----------------------------------------------------------------
3. DESIGN REASONING (why I built it this way)
----------------------------------------------------------------

- A lone comma vs a comma-chord requires deferring the comma output. The
  clean Karabiner primitive for "do X only if nothing follows within N
  ms" is to_delayed_action (to_if_invoked). Pressing any next key cancels
  it, which is exactly the leader semantics I want, and it also makes
  ", ," collapse to one comma.

- Sticky modifiers were the obvious fit for "arm ⌘, then apply it to the
  next key," because Karabiner's sticky_modifier auto-clears after the
  next real key and multiple sticky modifiers STACK. That gives ⌘⌥ for
  free without tracking modifier state myself.

- The hard part was chording: after ", f", the next d must mean "also arm
  ⌥", not "type d". Karabiner has no way to say "intercept a/s/d/f only
  while a sticky modifier happens to be armed" — sticky modifiers aren't
  queryable as conditions. So I need a second explicit state
  (comma-mod-layer) purely to keep intercepting a/s/d/f as
  modifier-adders.

- Why a SECOND variable and not just reuse comma-layer? Because the same
  physical key must behave differently in the two states: with no
  modifier, ", q" beeps; with a modifier, "q" must pass through as ⌘Q.
  One variable can't encode both, so State A (leader) and State B
  (collecting) are distinct.

- The tricky requirement was clearing State B. If a non-modifier key just
  "fell through" to the base layer without clearing comma-mod-layer, the
  variable would stay set forever and later a/s/d/f in normal typing
  would be swallowed. But I can't use a catch-all { from: { any:
  "key_code" } } to clear it, because matching an event CONSUMES it —
  Karabiner has no "clear a variable and let the event continue"
  primitive, and `from.any` doesn't expose the key so it can't re-emit
  it.

- Resolution: rebuild State B from the base layer itself. For every
  base-layer key I emit "set comma-mod-layer=0, then the key's normal
  base behavior." This clears the state AND reproduces exactly what the
  key would have done (letters, symbols, and crucially the DUOS). Reusing
  the duos is what makes ", f <hold>[ q" work: [ still activates the
  symbol layer, and q on the symbol layer yields a quote, with ⌘ applied.

- Whitespace keys (tab/esc/space/enter/backspace) in State B are a
  deliberate choice: they apply the modifiers normally (⌘Tab, ⌘Enter,
  ...) rather than keeping the comma pass-through. That falls out
  naturally from "behave like the base layer" and needs no special-casing.


----------------------------------------------------------------
4. KNOWN ASSUMPTION / THING TO VERIFY
----------------------------------------------------------------

The ", f <hold>[ q" -> "⌘ '" path relies on a Karabiner semantic: a sticky
modifier stays armed across `set_variable`-only events (like the one that
activates the symbol layer) and is only consumed when an actual key
(q) is output. I'm fairly sure this holds — it's how most sublayer/hyper
setups behave — but it's the one runtime assumption I want to confirm. If
⌘ ever gets dropped on that path, the fix is to stop relying on
fall-through for [ and instead handle that key explicitly (activate the
symbol layer without a set_variable that could consume the modifier, or
re-assert the modifier).

5. WHERE TO LOOK / HOW TO REGENERATE
----------------------------------------------------------------

Source of truth:  index.ts
Generated output: output.json  (written by `npm start`)
Format check:     npx prettier --check index.ts

Relevant identifiers in index.ts:
  COMMA_LAYER_TIMEOUT_MS, beep, baseLayerComma,
  commaThen, commaTo, commaIgnore, commaStartModifier, commaLayer,
  collectStickyModifier, exitCommaModifierLayer, commaModifierLayer

To tweak:
  - timeout for lone comma:            COMMA_LAYER_TIMEOUT_MS
  - beep sound:                        beep.shell_command
  - which keys pass through as ",x":   commaThen(...) calls in commaLayer
  - direct shortcuts (, z -> ⌘Z etc.):  commaTo(...) calls in commaLayer
  - modifier assignments (a/s/d/f):    commaStartModifier / collectStickyModifier
